## Detailed Review

### Item: Generated artifact corpus

- Evidence: `licenses.json` (tracked, 12,354-line change in this branch), `sbom.cdx.json` (on disk, untracked), `review.md` (generated mirror of `AGENTS.md`).
- What it does: records license aggregation, SBOM, and agent reference.
- How it appears to work: `scripts/generate-sbom.mjs` and `scripts/sync-review-md.mjs`; `pnpm sbom`, `pnpm review:sync`.
- Dependencies: CI `sbom.yml`, `validate.yml` (`sync-review-md --check`).
- Current controls: `review.md` mirror is CI-checked; SBOM is uploaded as an artifact.
- Missing controls: no CI regeneration/verification of `licenses.json`; no license policy doc.
- Risks: license aggregate silently drifts; committed generated distracts reviewers.
- Recommended improvement: add a `--check` for `licenses.json` and a `LICENSE_POLICY.md`; stop tracking it or regenerate in CI.
- Suggested tests: CI step diffing `licenses.json`.
- Suggested docs: `docs/LICENSE_POLICY.md`.

### Item: Duplicate schema bootstrap

- Evidence: `docs/portal_platform_formal_handoff_bundle/supabase_consolidated_fresh_bootstrap_20260529.sql` and `supabase/migrations/5302026_supabase_consolidated_fresh_bootstrap_20260529.corrected.v3.sql`.
- What it does: two near-identical "fresh bootstrap" schema definitions.
- How it appears to work: the migration is live; the docs copy is a handoff bundle.
- Risks: an implementer may apply/patch the wrong file.
- Recommended improvement: mark the docs bundle historical/generated, or remove it.
- Suggested docs: note in `docs/` that `supabase/migrations` is the single source.

## Findings

### Finding ID: INV-P2-001 - Committed generated artifacts drift without a gate

- Severity: P2
- Confidence: High
- Area: INV
- Evidence:
  - `licenses.json` — tracked (12,354 lines changed in this branch); regenerable via a license tool
  - `sbom.cdx.json` — present on disk but untracked/gitignored (`.gitignore` lists it as generated)
  - `review.md` — generated mirror of `AGENTS.md` (`scripts/sync-review-md.mjs`)
  - `.github/workflows/validate.yml` — CI checks only the `review.md` mirror, not `licenses.json`/SBOM
- What is happening: generated output is committed/stored without a CI freshness check (SBOM) or with no check at all (licenses), so it silently diverges from the lockfile.
- Why it matters: stale compliance/supply-chain artifacts give a false sense of coverage.
- User / business impact: audit/compliance evidence may be out of date at review time.
- Security / privacy / reliability impact: low direct; medium supply-chain/compliance.
- Recommended fix: add `--check` regeneration for `licenses.json` in `test.yml`/`validate.yml`; either untrack `sbom.cdx.json` fully or generate at release and bind it to the SHA.
- Suggested validation: `node scripts/generate-sbom.mjs sbom.cdx.json && git diff --exit-code licenses.json`.
- Owner suggestion: platform/DevEx
- Effort estimate: S
- Dependencies: none
- Status: open

### Finding ID: INV-P2-002 - Duplicate schema bootstrap SQL can be mistaken for the source of truth

- Severity: P2

  - `supabase/migrations/5302026_supabase_consolidated_fresh_bootstrap_20260529.corrected.v3.sql`
- What is happening: a full schema bootstrap exists both as a docs handoff bundle and as the live migration.
- Why it matters: edits or fixes may target the wrong copy; the two can diverge.

- Security / privacy / reliability impact: medium reliability.
- Recommended fix: add a header marking the docs copy historical/generated, or delete it and link to migrations.
- Suggested validation: grep that only one bootstrap contains `alter table ... enable row level security` for core tables.

- Dependencies: none
- Status: open
