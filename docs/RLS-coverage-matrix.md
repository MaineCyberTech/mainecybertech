# RLS Coverage Matrix

> Research document for the planned **tenant-isolation hardening** (making Supabase RLS a live backstop instead of relying solely on middleware).
> Generated by static analysis of `supabase/migrations/*.sql`.

Note: there are **0** truly policy-less RLS tables. The danger the hardening must address is the **service_role-ONLY** set (see section 4).

## 2. Design decision (approved design "b")

- **Chosen: design (b)** - keep the **service-role** client as the default inside the API, exposed only through an audited `withServiceRole()` escape hatch. Do **NOT** bake platform-admin access into every RLS policy.
- Rationale: `public.is_org_member(org_id)` is defined in `5302026_..._v3.sql:653` and checks only `public.memberships` for `auth.uid()` - it has **no platform-admin branch**. The 8 `PLATFORM_ADMIN_KEYS` (`super_admin`, `admin`, `dispatcher`, `engineer`, `security-analyst`, `project-manager`, `finance`, `onboarding-specialist`, per `apps/api/src/lib/roles.ts:9-18`) are therefore **not** recognized by `is_org_member`. Any migration to a *user-scoped* client would silently break all cross-tenant admin operations unless they go through `withServiceRole()`.
- Consequence for policy authoring: new/rewritten policies should scope tenant data via `public.is_org_member(organization_id)` (or `is_org_approved_member`). Platform-admin cross-tenant access stays on the service-role escape hatch and is already audited via `impersonation_log` (migration `5302133`).

## 7. Methodology and caveats

- Scope labels (`member`, `owner`, `platform_admin`, `admin-key`, `org_admin`, `service_role`, `open`) are derived from keyword matching in each `CREATE POLICY` statement (`is_org_member`, `is_org_admin`, `auth.uid()`, `r.key in ('super_admin','admin')`, `to service_role`, `using (true)`). A policy whose USING/WITH CHECK uses a custom predicate not matching these keywords is labelled `member` by default - manually verify before acting.
- An "open" policy is detected only via a literal `using (true)`; policies like `using (status = 'active')` without `is_org_member` are also effectively non-tenant-scoped but may be mislabelled `member`.
- Statements were split on `;` for parsing; policies embedded in function bodies were excluded from the policy count.
- "Total tables" counts distinct `CREATE TABLE` in `supabase/migrations/` (140). 139 have RLS enabled; 1 table created without RLS is out of scope for this matrix.
